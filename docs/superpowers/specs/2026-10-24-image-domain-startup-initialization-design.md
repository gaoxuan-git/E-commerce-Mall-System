# 图片域名启动初始化设计

## 目标

应用启动时从现有 `GET /api/front/image/domain` 接口读取本地图片域名，并写入 `imgHost` 缓存，使地址空状态等依赖 `Cache.get('imgHost')` 的静态图片能够加载。

## 方案选择

采用全局启动初始化，而不是在地址页局部请求或硬编码静态资源主机：

- 全局初始化只请求一次，覆盖所有依赖 `imgHost` 的页面。
- 复用已有 `getImageDomain()` API，不新增接口和配置。
- 不硬编码端口，保持开发、测试和生产环境可配置。

## 数据流

1. `App.vue` 启动时调用 `getImageDomain()`。
2. 接口返回非空字符串后执行 `Cache.set('imgHost', domain)`。
3. 页面通过现有 `Cache.get('imgHost')` 读取图片域名并拼接静态资源路径。

## 错误处理

- 接口失败时不阻塞应用启动。
- 返回空值时不覆盖已有的有效缓存。
- 保留现有缓存作为接口短暂不可用时的降级值。

## 修改范围

- 修改 `frontend/uni-app/App.vue` 的 API 导入和启动初始化逻辑。
- 不修改地址页、接口协议、后端配置或其他页面。

## 验证

- 确认图片域名接口返回 `http://127.0.0.1:8080`。
- 完成 H5 构建。
- 冷启动后确认本地缓存存在 `imgHost`，且空地址图片请求返回 PNG。
