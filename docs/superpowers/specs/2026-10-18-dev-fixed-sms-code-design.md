# 开发环境固定短信验证码设计

## 背景

当前手机号登录、注册和修改密码依赖一号通短信服务。开发环境如果未登录一号通、未开通短信服务或额度不足，就无法完成本地账户流程测试。

本方案在本地 `dev` 环境提供固定验证码 `123456`，不调用外部短信服务；生产环境继续使用随机验证码和真实短信发送逻辑。

## 目标

- 仅在 Spring `dev` Profile 下启用固定短信验证码。
- 固定验证码为 `123456`。
- 保留手机号格式校验、Redis 有效期和 60 秒发送频率限制。
- 登录、注册、修改密码等现有验证码消费逻辑保持不变。
- 接口仍只返回“发送成功”，不在响应或日志中暴露验证码。
- 非 `dev` 环境默认关闭，继续使用现有一号通随机短信验证码。

## 非目标

- 不接入新的第三方“免费短信”供应商。
- 不修改滑块行为验证码。
- 不取消生产环境短信验证码。
- 不为固定验证码增加线上开关或管理后台入口。

## 方案比较

### 方案 A：短信服务内部增加开发环境固定码分支

在 `SmsServiceImpl.sendCommonCode` 中先执行现有手机号校验和发送频率校验。仅当固定码配置开启且当前 Profile 为 `dev` 时，直接将固定码写入 Redis，不调用一号通。

优点：

- 复用所有现有短信验证码入口。
- 登录、注册和修改密码无需分别修改。
- 生产逻辑保持原样。
- 改动范围小，容易测试和回退。

这是本次采用的方案。

### 方案 B：在 Controller 中直接返回固定码

改动简单，但会绕过短信服务的限流、有效期和统一存储逻辑，并可能把验证码暴露在接口响应中，因此不采用。

### 方案 C：接入第三方免费短信服务

通常仍需要账户、API Key 和有限免费额度，还会把手机号交给新的第三方处理，增加隐私、稳定性和供应商管理成本，因此不采用。

## 配置设计

在 `backend/crmeb-front/src/main/resources/application-dev.yml` 中增加：

```yaml
crmeb:
  sms:
    dev-fixed-code:
      enabled: true
      value: ${CRMEB_DEV_SMS_CODE:123456}
```

其他环境不配置该开关，代码默认值为 `false`。

服务端同时检查：

1. `crmeb.sms.dev-fixed-code.enabled=true`。
2. Spring 当前激活的 Profile 包含 `dev`。
3. 固定码符合六位数字格式。

三个条件全部满足时才允许使用固定码，防止开发配置被误带入其他环境。

## 数据流

```text
POST /api/front/sendCode?phone=...
  -> 校验手机号格式
  -> 检查 sms:validate:phone:{phone} 是否存在
  -> 判断是否为 dev 固定码模式
     -> 是：读取 sms_code_expire
            写入 sms:validate:code:{phone} = 123456
            写入 sms:validate:phone:{phone} = 1，TTL 60 秒
            返回发送成功
     -> 否：执行现有一号通短信发送逻辑
```

验证码消费流程不变：

```text
登录/注册/修改密码
  -> 从 Redis 读取 sms:validate:code:{phone}
  -> 比较用户提交值
  -> 成功后删除验证码
```

## 代码边界

### `SmsServiceImpl`

- 注入固定码开关和值。
- 注入 Spring `Environment`，判断当前是否激活 `dev`。
- 新增内部方法判断是否启用开发固定码。
- 新增内部方法写入固定码及频率限制键。
- 固定码模式在一号通账户检查之前返回。
- 不记录完整手机号或固定码日志。

### `application-dev.yml`

- 开启开发固定码。
- 默认值为 `123456`。
- 允许通过 `CRMEB_DEV_SMS_CODE` 覆盖，便于不同开发环境使用。

生产、beta 和 trip 配置文件不增加启用开关。

## 错误处理

- 手机号格式错误：沿用现有错误。
- 60 秒内重复发送：沿用“您的短信发送过于频繁，请稍后再试”。
- 固定码不是六位数字：拒绝发送并返回明确的开发配置错误。
- Redis 写入异常：按现有异常机制返回失败，不降级调用真实短信。
- 非 `dev` 环境：忽略固定码配置并走真实短信逻辑。

## 安全与隐私

- 固定码不能在生产环境激活。
- API 响应不返回固定码。
- 日志不打印固定码和完整手机号。
- 开发环境不调用第三方短信服务，因此不会新增手机号第三方传输。
- 固定码仍有 3 分钟有效期（以当前 `sms_code_expire` 配置为准），验证成功后删除。

## 测试

### 自动化测试

- `dev` + 开关开启：写入固定码和 60 秒限流键，不调用一号通。
- 同一手机号 60 秒内再次发送：返回频率限制错误。
- 开关关闭：不进入固定码分支。
- 非 `dev` Profile：即使开关误开也不进入固定码分支。
- 固定码格式非法：拒绝发送。

### 集成测试

- 启动 `dev` 环境服务。
- 使用专用测试手机号调用发送验证码接口，返回“发送成功”。
- 验证 Redis DB 10 中存在验证码键，TTL 接近当前配置的 3 分钟。
- 使用 `123456` 完成注册或验证码登录。
- 验证成功后验证码键被删除。
- 不调用真实短信接口。

### 回归测试

- 后端相关单元测试通过。
- 后端全量测试通过。
- H5 注册和验证码登录流程通过。

## 回退

删除 `application-dev.yml` 中的固定码配置，或将 `enabled` 改为 `false`，即可恢复开发环境的一号通短信发送逻辑，无需修改数据库。
