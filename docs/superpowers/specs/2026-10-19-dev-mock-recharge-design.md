# 本地开发模拟充值设计

## 背景

本地 H5 充值页当前会调用真实微信支付接口。由于本地数据库中的
`pay_weixin_appid` 等支付参数为空，点击“立即充值”后会提示缺少支付配置。

本地开发需要完整验证充值、余额持久化和余额购买流程，但不应配置真实支付
密钥，也不应调用微信、支付宝或其他第三方支付服务。

## 目标

- 仅在 Spring `dev` Profile 下提供模拟充值。
- 使用显式配置开关控制模拟充值能力。
- 模拟充值金额和套餐赠送金额真实写入本地数据库。
- 刷新页面后余额保持，并可用于后续余额支付购买。
- 创建正常的充值订单和余额账单，保证本地数据可审计。
- H5 开发模式显示“本地模拟支付”和明确的模拟充值成功提示。
- 生产、beta、trip 和管理 API 不提供模拟充值能力。
- 不修改真实微信、支付宝支付流程。

## 非目标

- 不模拟微信或支付宝签名、预下单和回调。
- 不生成或保存伪造的微信、支付宝密钥。
- 不在生产环境提供后台开关或管理入口。
- 不修改订单余额支付的既有业务逻辑。
- 不为模拟充值提供退款能力。

## 方案比较

### 方案一：新增 dev 专用模拟充值接口

新增独立的开发环境 Controller 和 Service。接口创建充值订单并复用现有
`RechargePayService.paySuccess()` 完成订单支付、余额增加和账单记录。

优点：

- 模拟支付与真实支付入口完全分离。
- 可通过 Profile 和配置开关双重隔离。
- 复用现有充值成功业务，数据结构与真实充值一致。
- 易于测试、审计和删除。

这是本次采用的方案。

### 方案二：在现有微信充值接口内增加 dev 分支

改动较少，但模拟逻辑和真实支付逻辑混在同一入口。环境判断或配置错误时，
更容易影响生产支付，因此不采用。

### 方案三：仅在前端显示充值成功

不会更新数据库，刷新后余额丢失，也无法完成后续余额购买，不符合需求。

## 配置设计

仅在 `backend/crmeb-front/src/main/resources/application-dev.yml` 增加：

```yaml
crmeb:
  payment:
    dev-mock-recharge:
      enabled: true
```

其他 Profile 不配置该开关。代码默认值为 `false`。

模拟充值 Controller 同时要求：

1. 当前 Spring Profile 包含 `dev`。
2. `crmeb.payment.dev-mock-recharge.enabled=true`。

两个条件全部满足时才注册接口。

## 接口设计

### 模拟充值

```text
POST /api/front/recharge/dev/mock
Authorization: Bearer <token>
Content-Type: application/json
```

请求复用现有充值参数：

```json
{
  "price": 30.00,
  "rechar_id": 123
}
```

规则：

- `rechar_id > 0` 时，以服务端套餐配置的金额和赠送金额为准。
- `rechar_id` 为空或小于等于零时，使用客户端提交的自定义金额，赠送金额为零。
- 客户端提交的用户 ID、赠送金额、支付渠道均不可信且不参与处理。

成功响应：

```json
{
  "code": 200,
  "data": {
    "mock": true,
    "orderNo": "recharge...",
    "rechargeAmount": 30.00,
    "giveAmount": 3.00,
    "creditedAmount": 33.00,
    "balance": 33.00
  }
}
```

## 组件设计

### `DevMockRechargeController`

- 放置在 `crmeb-front` 模块。
- 使用 `@Profile("dev")`。
- 使用 `@ConditionalOnProperty` 检查显式开关。
- 复用前台现有鉴权机制，只允许已登录用户调用。
- 不接受用户 ID，不直接操作数据库。

### `DevMockRechargeService`

- 仅在 `dev` Profile 和开关开启时创建 Bean。
- 读取当前登录用户。
- 校验充值金额和套餐。
- 创建模拟充值订单。
- 调用 `RechargePayService.paySuccess()` 完成充值成功处理。
- 返回充值明细和最新余额。

### `DevMockRechargeResponse`

返回模拟标识、订单号、充值金额、赠送金额、到账总额和最新余额。前端使用
返回余额刷新 Pinia 用户状态，不自行计算最终余额。

## 数据流

```text
本地 H5 选择充值金额
  -> POST /api/front/recharge/dev/mock
  -> 校验 dev Profile 和显式开关
  -> 从登录上下文读取当前用户
  -> 校验套餐或自定义金额
  -> 创建 rechargeType=dev_mock 的充值订单
  -> 保存 eb_user_recharge
  -> RechargePayService.paySuccess()
     -> 标记充值订单 paid=true
     -> 更新 eb_user.now_money
     -> 写入 eb_user_bill
  -> 返回最新余额
  -> 前端更新用户状态并显示“模拟充值成功”
```

固定套餐的赠送金额必须从服务端套餐配置读取。充值到账金额为：

```text
creditedAmount = rechargeAmount + giveAmount
```

## 事务与一致性

模拟充值 Service 使用事务包裹以下操作：

1. 保存充值订单。
2. 标记充值订单已支付。
3. 增加用户余额。
4. 保存余额账单。

任一步骤失败均抛出业务异常并回滚。`RechargePayService.paySuccess()` 返回失败
时，不返回模拟充值成功。

模拟订单使用唯一订单号，`rechargeType` 固定为 `dev_mock`，便于与真实充值
区分。余额账单通过 `linkId` 关联该模拟充值订单。前端提交期间禁用充值按钮，
避免用户重复点击。

## 金额与套餐校验

- 用户必须已登录且状态正常。
- 固定套餐必须存在并处于可用状态。
- 套餐金额和赠送金额只信任服务端配置。
- 自定义金额不能为空且必须大于零。
- 自定义金额不得低于 `store_user_min_recharge`。
- 自定义金额不得超过 `50000` 元。
- 所有金额使用 `BigDecimal`，不使用浮点运算。
- 赠送金额为空时按零处理。

## 前端设计

修改 H5 充值页：

- 仅在 H5 开发构建中启用模拟充值分支。
- 支付方式显示“本地模拟支付”，不显示微信或支付宝支付。
- 按钮文案显示“模拟充值”。
- 点击后调用模拟充值专用接口。
- 请求处理中禁用按钮并显示加载状态。
- 成功后使用接口返回的最新余额更新用户状态。
- 显示“模拟充值成功”，随后进入余额页面。
- 失败时恢复按钮并展示服务端错误，不修改本地余额。

生产 H5、App 和小程序继续使用原有支付代码。

## 安全边界

- 非 `dev` Profile 时 Controller Bean 不存在。
- 开关默认关闭，只有前台 API 的 `application-dev.yml` 开启。
- 生产、beta、trip 和管理 API 不添加开关。
- 接口使用现有登录鉴权，不能为其他用户充值。
- 服务端不信任客户端的用户 ID、赠送金额和支付状态。
- 模拟充值不调用微信、支付宝及任何第三方网络接口。
- 不在日志中记录 Token、支付密钥或完整请求体。
- 返回数据明确包含 `mock=true`，页面明确标识“本地模拟支付”。

## 错误处理

- 未登录：返回现有未登录错误。
- 套餐不存在或已下架：返回“您选择的充值方式已下架”。
- 金额非法：返回明确的金额校验错误。
- 订单保存失败：返回“生成模拟充值订单失败”。
- 充值成功处理失败：返回“模拟充值失败，请重试”并回滚。
- 非 dev 或开关关闭：接口不存在，不降级到真实支付。

## 测试设计

### 后端自动化测试

- `dev` + 开关开启时注册模拟充值接口。
- 非 `dev` Profile 时接口不注册。
- 开关关闭时接口不注册。
- 固定套餐使用服务端金额和赠送金额。
- 自定义金额充值时赠送金额为零。
- 非法金额、低于最低金额和超过上限均被拒绝。
- 套餐不存在或已下架时被拒绝。
- 充值订单保存失败时不增加余额。
- 充值成功处理失败时事务回滚。
- 正常充值会返回最新余额和 `mock=true`。

### 集成测试

- 记录测试用户充值前余额。
- 使用固定套餐执行模拟充值。
- 验证充值金额和赠送金额同时到账。
- 验证 `eb_user_recharge` 为已支付且类型为 `dev_mock`。
- 验证 `eb_user_bill` 存在对应收入记录。
- 刷新页面后余额保持。
- 使用充值余额完成一次商品余额支付。
- 验证没有微信或支付宝网络请求。

### 前端验证

- H5 开发构建显示“本地模拟支付”和“模拟充值”。
- 重复点击时只提交一次请求。
- 成功后余额立即更新并显示成功提示。
- 失败时不修改余额。
- H5 生产构建不包含可用的模拟充值入口。

## 回退

将 `crmeb.payment.dev-mock-recharge.enabled` 改为 `false` 或删除配置后，
模拟充值接口不再注册。删除 H5 开发分支即可完全移除模拟充值功能，不需要
修改数据库中的真实支付配置。
