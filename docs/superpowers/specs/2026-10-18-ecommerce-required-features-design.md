# 电商必备功能补齐设计

## 1. 目标

严格满足项目根目录 `功能.md` 中的 9 项移动端功能要求，并验证移动端、商城 API、管理 API、MySQL 和 Redis 之间的关键业务链路。

本次补齐四个已确认缺口：

1. 购物车批量下单时展示下单过程进度。
2. 个人详情页提供明确的切换账号操作。
3. 侧边导航提供登录、注册、切换账号和退出登录。
4. 登录页提供独立注册账号流程，并由真实后端接口完成注册。

## 2. 范围

### 2.1 包含

- 商城移动端 uni-app 页面与组件。
- 商城前台注册 API 和登录服务。
- 后端请求模型与自动化测试。
- H5、App 构建检查。
- 本地商城 API、管理 API 和浏览器端到端验证。
- 更新功能实现对照文档。

### 2.2 不包含

- 不修改数据库结构。
- 不重构原有订单核心事务。
- 不接入真实短信供应商或真实支付扣款。
- 不保存多个账号的密码、验证码或长期令牌。
- 不修改现有商品、订单和用户表的业务含义。

## 3. 方案

采用项目原生补齐方案：

- 注册复用现有手机号、短信验证码、用户创建和令牌签发能力。
- 侧边导航复用全局注册的 `base-drawer` 组件。
- 切换账号复用服务端退出接口和 Pinia `LOGOUT` 状态清理。
- 下单进度使用真实客户端阶段，不伪造服务端内部执行百分比。

不采用纯前端假注册方案，因为它不能证明注册接口打通；不采用异步任务式下单进度方案，因为当前同步订单 API 无需为 UI 要求重构为任务系统。

## 4. 组件与职责

### 4.1 注册请求模型

新增 `RegisterRequest`：

- `account` 映射手机号。
- `captcha` 映射六位短信验证码。
- `password` 使用统一密码规则。
- `spread_spid` 保留推广人关系。

请求模型只负责输入校验和字段映射，不包含业务逻辑。

### 4.2 注册服务

在 `LoginService` 增加 `register`，由 `LoginServiceImpl` 实现：

1. 检查手机号是否已注册且账号未注销。
2. 校验并消费短信验证码。
3. 调用现有 `registerPhone` 创建用户。
4. 设置用户提交的加密密码。
5. 签发登录令牌并返回 `LoginResponse`。

注册流程使用事务。创建用户或设置密码任一步失败时整体回滚，避免产生只有随机密码的半成品账号。

### 4.3 注册接口

在商城 `LoginController` 增加：

`POST /api/front/register`

成功返回与登录相同的 `LoginResponse`，移动端可立即进入已登录状态。

### 4.4 登录页注册模式

登录页保留原有：

- 账号密码登录。
- 手机验证码快速登录。
- App 微信和 Apple 登录。

新增注册模式：

- 手机号输入。
- 验证码发送和输入。
- 密码输入。
- 用户协议和隐私政策勾选。
- “注册并登录”提交按钮。
- “返回登录”入口。

注册成功后写入 Pinia 登录态、读取用户信息并返回原目标页面。

### 4.5 账户侧边导航

新增 `AccountDrawer` 组件，放置在个人中心页：

- 未登录：显示“登录/注册”。
- 已登录：显示头像、昵称、个人资料、切换账号、退出登录。
- 点击遮罩或关闭图标关闭抽屉。

个人中心顶部增加菜单图标打开抽屉。组件只处理账户导航，不承载商城业务菜单。

### 4.6 切换账号

个人详情页增加“切换账号”操作：

1. 请求服务端退出当前令牌。
2. 无论服务端令牌是否已过期，都清除本地 Pinia 和缓存登录态。
3. 使用 `reLaunch` 进入登录页，并标记为主动切换账号。

切换账号不记录历史账号列表，不保存密码。

### 4.7 下单过程进度

确认订单页新增全屏进度层和进度条：

| 阶段 | 进度 | 触发条件 |
|---|---:|---|
| 校验订单信息 | 20% | 用户点击提交且开始校验 |
| 提交订单 | 55% | 本地校验通过，调用创建订单 API |
| 订单创建成功 | 85% | API 返回订单号 |
| 进入支付 | 100% | 准备跳转支付页 |

失败时：

- 显示失败状态和服务端错误。
- 关闭提交锁。
- 保留当前确认订单数据。
- 用户可重试。

进度层显示期间禁止重复提交。

## 5. 数据流

### 5.1 注册

```text
注册表单
  -> POST /api/front/sendCode
  -> Redis 保存验证码
  -> POST /api/front/register
  -> 校验手机号、验证码、密码
  -> eb_user 创建用户并写入加密密码
  -> Redis/JWT 令牌
  -> Pinia 保存登录态
  -> GET /api/front/user
```

### 5.2 切换账号

```text
切换账号
  -> GET /api/front/logout
  -> 服务端清理当前令牌
  -> Pinia.LOGOUT 清除本地令牌、UID、用户信息和授权缓存
  -> 登录页
```

### 5.3 批量下单

```text
购物车勾选多个商品
  -> POST /api/front/order/pre/order
  -> 确认订单页
  -> 进度 20%
  -> POST /api/front/order/create
  -> 进度 85%
  -> 支付页
  -> 进度 100%
```

## 6. 错误处理

| 场景 | 用户结果 | 状态处理 |
|---|---|---|
| 手机号格式错误 | 表单提示 | 不发请求 |
| 密码不符合规则 | 表单提示规则 | 不发请求 |
| 验证码错误或过期 | 显示服务端提示 | 保留表单 |
| 手机号已注册 | 提示使用登录 | 保留手机号 |
| 注册创建失败 | 显示错误 | 事务回滚 |
| 服务端退出失败 | 仍清除本地登录态 | 避免旧身份继续使用 |
| 下单校验失败 | 显示字段提示 | 不显示提交中状态 |
| 创建订单失败 | 进度层退出并显示错误 | 解锁提交按钮 |
| 重复点击提交 | 忽略后续点击 | 只发送一次创建请求 |

## 7. 验收标准

### 7.1 九项移动端功能

1. App 启动后可显示引导页并进入首页。
2. 首页和分类页可展示分类与商品。
3. 点击商品进入对应详情页。
4. 详情页可选择规格、数量并加入购物车。
5. 购物车可删除、全选或多选商品，下单时展示进度。
6. 订单列表可展示订单，并删除符合条件的订单。
7. 个人详情可展示信息、修改密码和切换账号。
8. 个人中心侧边导航可登录和退出登录。
9. 登录页可进入注册模式并创建新账号。

### 7.2 服务端管理功能

- 管理后台可展示、新增、编辑、上下架和删除商品。
- 管理后台可展示订单详情、发货、退款和删除符合条件的订单。

## 8. 测试设计

### 8.1 自动化层级

- 60% 小型测试：请求校验、注册分支、状态辅助函数。
- 30% 中型测试：商城 API 与本地 MySQL、Redis 集成。
- 10% 大型测试：H5 浏览器关键路径。

### 8.2 阻断检查

| 阶段 | 检查 | 失败响应 |
|---|---|---|
| 开发 | 后端目标测试 | 定位失败分支，修复后重跑目标测试 |
| 开发 | H5 与 App 构建 | 修复编译错误，不进入浏览器测试 |
| 集成 | 注册、登录、商品、购物车、订单 API | 停止端到端流程并检查接口响应和服务日志 |
| 验收 | 浏览器关键路径 | 保存截图和控制台错误，修复后从失败步骤重跑 |

阻断测试目标运行时间为 10 分钟内；以本次本机实测时长为记录来源，不使用估算值冒充历史 p95。

### 8.3 测试数据

- 使用专用测试手机号和本地 Redis 验证码。
- 测试密码只用于本地测试账号。
- 测试生成的购物车和订单通过测试账号隔离。
- 不复制生产用户数据，不输出令牌、密码或完整手机号到交付文档。

### 8.4 稳定性

- 构建和测试禁用外部业务网络依赖。
- 浏览器测试只访问本地服务。
- 若同一检查重跑不一致率超过 1%，在 24 小时内修复；无法立即修复时从阻断集合移出并记录到期时间。
- 构建缓存以锁文件、源文件和环境配置为输入；最终验收至少执行一次无旧产物依赖的构建。

## 9. 完成定义

只有在以下证据全部存在时才算完成：

- 四个缺口均有可操作页面和真实逻辑。
- 后端目标测试通过。
- H5 与 App 构建通过。
- 本地商城和管理 API 健康。
- 浏览器完成关键用户路径，控制台无新增错误。
- `功能实现对照说明.md` 更新为 9 项全部实现，并附测试结果。
